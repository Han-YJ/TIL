# focus 핸들러에서 입력값을 바꾸면 전체 선택이 풀린다

금액 칸은 평소 `10,000`처럼 쉼표를 넣어 보여 주고, 커서가 들어오면 `10000`으로 바꿔 편집하게 했다. 그런데 e2e에서 이 칸에 `12345`를 넣으면 `1000012345`로 저장됐다. 새로 친 값이 기존 값을 덮어쓰지 않고 뒤에 붙은 것이다.

## 원인 1 — 값을 바꾸면 선택이 사라진다

`input.value`에 새 값을 넣으면 그때까지 잡혀 있던 선택 범위가 풀리고 커서가 맨 끝으로 간다. 칸에 들어올 때 전체 선택이 됐더라도 focus 핸들러에서 표시값을 바꾸는 순간 그 선택이 없어진다. 그 상태에서 타이핑하면 기존 값 뒤에 이어 붙는다.

Tab으로 들어오는 실제 사용자도 같은 일을 겪는다. Chromium에서 측정한 결과는 이렇다.

| 진입 방식 | focus 핸들러 | 입력 결과 |
|---|---|---|
| Tab | 값만 바꿈 | `1000012345` |
| Tab | 값을 바꾸고 `select()` | `12345` |

## 원인 2 — focus 핸들러 안에서 본 선택 범위가 실제와 다르다

처음에는 이렇게 고쳤다. 전체 선택 상태였을 때만 값을 바꾼 뒤 다시 전체 선택한다. 마우스로 클릭해서 들어온 경우까지 전체 선택해 버리지 않으려고 조건을 둔 것이다.

```js
const all = el.selectionStart === 0 && el.selectionEnd === el.value.length;
el.value = raw;
if (all) el.select();
```

Tab으로 들어올 때는 이 수정이 통했지만, Playwright `fill`에서는 여전히 값이 뒤에 붙었다.

`fill`은 내부적으로 `select()`를 먼저 부르고 그다음 `focus()`를 부른다. 이 순서로 호출하면 Chromium의 focus 핸들러 안에서는 선택 범위가 `0,0`으로 보인다. 같은 칸을 `setTimeout` 뒤에 다시 읽으면 `0,6`, 즉 전체 선택이다. 선택은 실제로 일어났지만 focus 이벤트가 끝난 뒤에야 반영되는 것이다.

| 진입 방식 | focus 안에서 읽은 범위 | 이벤트 뒤에 읽은 범위 |
|---|---|---|
| Tab | `0,6` | — |
| `select()` → `focus()` (Playwright `fill`) | `0,0` | `0,6` |

그래서 조건문은 "전체 선택이 아니다"라고 판단하고 다시 선택하지 않았다.

| focus 핸들러 | `fill('12345')` 결과 |
|---|---|
| 값만 바꿈 | `1000012345` |
| 전체 선택이었을 때만 다시 선택 | `1000012345` |
| 항상 다시 선택 | `12345` |

## 해결

focus 안에서 선택 범위를 읽어 판단하지 않고, 표시값을 바꾼 뒤에는 항상 `select()`를 부른다. React에서는 값을 바꾸는 렌더가 `select()`보다 먼저 끝나야 하므로 `flushSync`로 감싼다.

```tsx
onFocus={(event) => {
  const input = event.currentTarget;
  flushSync(() => setFocused(true)); // 표시값 → 원값
  input.select();
}}
```

대신 마우스로 클릭해서 들어와도 전체 선택이 된다. Chromium에서 칸 중간을 클릭해도 선택 범위가 `0,5`로 남았다. 금액 칸은 보통 값을 통째로 바꾸므로 이 동작을 받아들였다. 클릭한 자리에 커서를 두어야 하는 칸이라면 `pointerdown`으로 진입 방식을 따로 기록해 두고 분기해야 한다.

## 정리

- focus 핸들러에서 입력값을 바꾸면 선택이 풀린다. 선택을 유지해야 하면 값을 바꾼 뒤 다시 선택해야 한다.
- focus 핸들러 안의 `selectionStart`·`selectionEnd`는 진입 방식에 따라 실제 선택보다 늦게 반영된다. 이 값으로 분기하는 코드는 프로그래밍 방식의 포커스, 즉 테스트 도구에서 틀린다.
- e2e가 앱 결함을 잡았는데 첫 수정이 통하지 않으면, 두 번째 추측으로 고치기 전에 최소 HTML로 이벤트 순서를 직접 재 보는 편이 빨랐다.
