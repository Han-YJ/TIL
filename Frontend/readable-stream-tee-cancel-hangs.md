# 복제된 응답 본문은 한쪽만 `cancel()` 하면 끝나지 않는다

버릴 응답의 연결을 빨리 돌려주려고 `await response.body?.cancel()` 을 쓰는 경우가 있다. 401 을 받고 재시도하기 전에 이전 응답을 정리할 때가 대표적이다. 브라우저나 Node 의 날 fetch 응답이면 바로 끝난다. 그런데 본문이 `tee()` 로 두 갈래로 복제된 응답이면 이 `await` 가 영원히 끝나지 않는다.

## 왜 멈추나

Streams 명세에서 `tee()` 로 나뉜 두 갈래는 원본 스트림 하나를 같이 쓴다. 한 갈래의 `cancel()` 이 돌려주는 Promise 는 **다른 갈래도 취소돼야** 원본 취소와 함께 풀린다. 다른 갈래를 아무도 읽거나 취소하지 않으면 계속 pending 이다.

```js
const [a, b] = new Response('x').body.tee();
await a.cancel(); // b 를 건드리지 않는 한 끝나지 않는다
```

## 어디서 만나나

내가 직접 `tee()` 를 부르지 않아도 프레임워크가 해 둘 수 있다. Next.js 서버 쪽 `fetch` 는 데이터 캐시·요청 중복 제거를 위해 응답을 복제해 둔다. 그래서 서버 컴포넌트에서 받은 응답에 `await response.body.cancel()` 을 걸면 렌더가 거기서 멈추고, 브라우저는 응답을 못 받은 채 계속 로딩한다.

단위 테스트는 보통 가짜 `Response`(한 갈래 본문)로 돌기 때문에 통과한다. 실제 서버에서 그 분기(예: 인증은 유효한데 API 만 401)를 탈 때만 드러난다.

## 정리

- 버릴 본문은 기다리지 않는다: `void response.body?.cancel().catch(() => {})`
- 또는 끝까지 읽어서 버린다: `await response.arrayBuffer()`
- `cancel()` 을 `await` 해야 한다면, 테스트도 `tee()` 한 응답으로 만든다
