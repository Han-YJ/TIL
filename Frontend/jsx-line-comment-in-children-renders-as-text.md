# JSX의 `//` 주석은 자리에 따라 주석이 되기도 하고 텍스트가 되기도 한다

컨트롤에 왜 이 클래스를 거는지 사유를 남기려고 `//` 두 줄을 컴포넌트 안에 적었다. 타입체크도 린트도 통과했다. 그런데 **그 두 줄이 화면에 글자로 찍히고 있었다.**

## 재현

같은 파일 안에서 세 자리에 주석을 넣어 보면 갈린다.

```tsx
export function A() {
  return (
    <div
      id="a"
      // 속성 자리 주석
      title="t"
    >
      // children 자리 주석
      <span>x</span>
      {/* 컨테이너 주석 */}
    </div>
  );
}
```

esbuild 트랜스폼 결과(`--jsx=automatic`):

```js
jsxs("div", {
  id: "a",
  title: "t",
  children: [
    "// children 자리 주석",        // ← 문자열로 남았다
    jsx("span", { children: "x" })
  ]
})
```

속성 자리와 `{/* */}` 는 사라졌다. **children 자리 한 줄만 문자열 리터럴이 됐다.**

## 왜 갈리나

파서가 그 지점에서 무엇을 읽고 있는지가 다르다.

여는 태그 **안쪽**(`<div` 와 `>` 사이)은 속성 목록이고 여기는 JS 문법 영역이다. 그래서 `//` 가 평범한 주석으로 먹힌다.

태그와 태그 **사이**는 `JSXText` 다. 여기서는 공백과 다른 요소를 빼면 **적힌 그대로가 텍스트**다. `//` 에 아무 의미가 없다. 주석을 두려면 JS 영역으로 한 번 들어갔다 나와야 하고, 그게 `{/* */}` 다 — 중괄호가 JSX 표현식 컨테이너를 열고 그 안에 블록 주석만 담기니 남는 값이 없어 아무것도 렌더되지 않는다.

즉 **주석이냐 텍스트냐를 가르는 것은 내용이 아니라 위치**다. 똑같은 문장이 두 줄 위에 있으면 사라지고 두 줄 아래에 있으면 화면에 뜬다.

## 실패가 조용하다

세 가지가 동시에 성립한다.

- **타입체크 통과** — 문자열은 유효한 `ReactNode` 다. 검사할 거리가 없다.
- **린트 통과** — 실제로 이 결함을 품은 채 `eslint` 가 error 0 으로 끝났다.
- **에러 없이 렌더** — 그냥 글자가 하나 더 그려질 뿐이다.

증상이 "깨진다"가 아니라 **"조금 길어진다"** 로 나온다. 실측한 사례에서는 모달 높이가 500px 에서 656px 로 늘었다. 주석 두 줄이 두 군데 있었고 그 156px 이 전부 글자였다.

그래서 수치 검사에도 잘 안 걸린다. 스냅샷이 없으면 "원래 그 정도였나" 하고 넘어간다. 눈으로 보면 명백한데, 눈으로 보는 단계가 파이프라인에 없으면 끝까지 산다.

## 확인법 — 트랜스폼 결과를 본다

의심되면 그 파일 하나만 트랜스폼해서 `children` 배열에 문자열이 섞였는지 본다.

```
esbuild --jsx=automatic Foo.tsx
```

`children: [ "// …", jsx(...) ]` 처럼 문자열이 앞에 붙어 있으면 그것이다. `tsc --jsx react-jsx` 로 실제 emit 을 떠도 같은 게 보인다. **`--noEmit` 으로는 안 보인다** — 타입만 보고 산출물을 안 만들기 때문이다.

찾을 때는 "`//` 가 있는 줄"이 아니라 **"바로 윗줄이 `>` 나 `}` 로 끝나는 `//` 줄"** 을 찾는다. 윗줄이 `>` 면 여는 태그가 닫힌 뒤이므로 children 자리이고, 속성 자리라면 윗줄이 속성 하나로 끝난다.

## 해법

- `{/* … */}` 로 감싼다 — 그 자리에 주석을 꼭 둬야 하면.
- **`return` 위로 옮긴다** — 대개 이쪽이 낫다. JSX 안에 사유를 적고 싶어지는 순간은 보통 그 사유가 마크업이 아니라 **그 컴포넌트의 결정**에 관한 것이라서, 함수 본문 쪽이 제자리다.

## 넓혀 보면

이 결함의 성질은 "실수했다"보다 **"같은 글자가 문맥에 따라 다른 것이 된다"** 쪽이다. 하나의 파일 안에 문법 영역이 두 개 겹쳐 있고 경계가 눈에 안 보인다. JSX 를 쓰는 동안 계속 그 경계를 넘나들지만 평소엔 태그와 중괄호가 표시를 해 줘서 의식하지 않는다. 주석은 그 표시가 없는 몇 안 되는 자리다.

비슷한 자리가 하나 더 있다. children 자리의 `{false}` `{null}` `{undefined}` 는 아무것도 안 그리는데 **`{0}` 은 `0` 을 그린다.** `arr.length && <List/>` 가 빈 배열에서 화면에 `0` 을 남기는 그 문제다. 원인은 다르지만 결론이 같다 — **children 자리에 놓인 값은 "안 보이겠지"가 기본값이 아니다.**

그리고 이 결함이 셋 다 통과한 게(타입·린트·에러 없음) 우연은 아니다. 정적 검사는 "이 값이 유효한가"를 보지 그 값이 **의도된 것인가**를 보지 않는다. 의도는 화면에만 남는다.
