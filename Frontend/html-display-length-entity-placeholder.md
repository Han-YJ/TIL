# 리치 에디터 글자 수는 원문 길이가 아니다 — 엔티티를 공백으로 치환하면 또 틀린다

리치 텍스트 에디터에 2000자 제한을 걸었다. "서식은 글자 수에 들지 않아요"라고 안내까지 띄웠는데, 화면에 400자쯤 보이는 글이 저장에서 막혔다.

에디터가 내주는 값은 평문이 아니라 HTML이다.

```html
<p>A &amp; B</p>
```

사용자가 보는 건 `A & B` — 5자다. 그런데 `value.length`는 21자다.

## 태그만 벗기면 절반만 고친 것이다

먼저 떠오르는 건 태그 제거다.

```ts
html.replace(/<[^>]*>/g, '').length
```

`A &amp; B` → 9자. 아직 5자가 아니다. **HTML 엔티티가 원문 길이 그대로 남아 있다.** `&amp;`는 5자, `&nbsp;`는 6자, `&#x1F600;`은 9자로 세어진다.

특수문자가 많은 글에서 이 차이는 배로 벌어진다. `&`를 500번 쓴 글은 화면엔 500자인데 계산은 2500자가 되고, 상한이 2000이면 저장이 막힌다. 사용자 입장에선 400자짜리 글이 거부당하는 셈이다.

엔티티는 **무엇으로 변환되든 결국 1글자**다. 그러니 길이만 맞추면 되고, 실제 문자로 디코드할 필요는 없다.

```ts
const HTML_ENTITY = /&(?:[a-z][a-z0-9]{1,30}|#\d{1,7}|#x[0-9a-f]{1,6});/gi;
```

## 그 자리표시를 공백으로 두면 이번엔 과소 계산된다

여기서 한 겹 더 있다. 엔티티를 공백으로 치환하는 코드를 흔히 보는데, 이러면 **문자열 경계의 엔티티가 `trim()`에 먹힌다.**

앞뒤 공백을 떼는 건 보통 맞는 처리다. `<p>  </p>`처럼 공백만 남은 입력을 "빈 값"으로 봐야 하니까. 문제는 순서다.

```ts
'&lt;code&gt;'
  .replace(/<[^>]*>/g, '')
  .replace(HTML_ENTITY, ' ')   // ' code '
  .trim()                       // 'code' → 4자
  .length                       // 4  ❌ 실제로는 <code> 6자
```

앞뒤 `<`, `>`가 공백이 됐다가 `trim()`에 통째로 사라진다. 경계에 엔티티가 없는 입력은 멀쩡히 통과하기 때문에, 이 버그는 **경계값 테스트에서만 드러난다.**

그래서 자리표시는 공백이면 안 된다. 눈에 안 띄면서 공백이 아닌 문자가 필요하고, `U+FFFC`(OBJECT REPLACEMENT CHARACTER)가 그 용도로 정의된 문자다.

```ts
const PLACEHOLDER = '￼';

export function displayLength(html: string): number {
  return html
    .replace(/<[^>]*>/g, '')
    .replace(/&nbsp;/gi, ' ')      // 이것만 진짜 공백이다
    .replace(HTML_ENTITY, PLACEHOLDER)
    .trim().length;
}
```

`&nbsp;`만 예외로 먼저 뺀다. 이건 화면에서 실제로 공백이라, 공백 취급을 받아야 맞다. `<p>&nbsp;</p>`는 빈 값으로 판정돼야 한다.

## 세는 축을 먼저 정한다

정리하면 이 함수가 답해야 할 질문은 하나다 — **원문을 세는가, 표시되는 글을 세는가.**

| 대상 | 원문 길이 | 표시 길이 |
|---|---|---|
| `<b>hi</b>` | 10 | 2 |
| `&amp;` | 5 | 1 |
| `&nbsp;` | 6 | 1 (공백) |
| 앞뒤 공백 | 포함 | 제거 |

사용자에게 카운터를 보여주는 순간 축은 표시 길이로 고정된다. 저장 검증도 같은 함수를 써야 한다. 카운터와 검증이 각자 계산하면 "화면엔 400/2000인데 저장이 안 되는" 상태가 만들어진다.

## 테스트

경계와 다중 엔티티를 함께 잠근다. 가운데 엔티티만 검증하면 `trim()` 함정을 못 잡는다.

```ts
expect(displayLength('<p>A &amp; B</p>')).toBe(5);
expect(displayLength('&lt;code&gt;')).toBe(6);        // 경계 — 공백 치환이면 4로 샌다
expect(displayLength('<p>&nbsp;</p>')).toBe(0);       // 공백만 있으면 빈 값
expect(displayLength('&amp;'.repeat(500))).toBe(500);
```
