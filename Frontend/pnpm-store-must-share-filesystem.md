# pnpm 스토어는 node_modules 와 같은 파일시스템이어야 한다 — 아니면 조용히 폴백한다

CI 캐시를 pnpm 스토어 경로에 걸어 뒀는데 **몇 주 동안 빈 채로 돌고 있었다.** 매 런 1,100여 패키지를 `reused 0` 으로 새로 받으면서. 에러가 아니라 **그냥 느려지기만** 해서 아무도 몰랐다.

## 메커니즘

pnpm 은 패키지를 `node_modules` 에 복사하지 않고 **전역 스토어에서 하드링크**로 건다. 그래서 설치가 빠르고 디스크를 덜 쓴다.

그런데 **하드링크는 파일시스템 경계를 넘지 못한다.** 스토어가 `node_modules` 와 다른 마운트에 있으면 링크를 걸 수 없다.

pnpm 은 이때 실패하지 않고 **프로젝트 옆(`<workspace>/.pnpm-store`)으로 스토어를 옮겨** 설치를 계속한다. 합리적인 폴백인데, **설정한 경로에는 아무것도 안 쌓인다**는 뜻이기도 하다.

컨테이너 CI 에서는 이 조건이 쉽게 성립한다. 홈 디렉터리와 체크아웃 디렉터리가 다른 마운트인 이미지가 흔하다.

```yaml
# 캐시는 여기를 본다
caches:
  pnpm: ~/.local/share/pnpm/store
```
```
# 그런데 pnpm 은 여기에 쌓는다
<clone-dir>/.pnpm-store/
```

두 경로가 영영 안 만난다. 캐시는 매번 비어 있고, 매번 전부 새로 받는다.

## 어떻게 눈치채나 — 대조군이 가른다

로그에서 **같은 스텝 안의 다른 캐시**와 비교하면 한 번에 좁혀진다.

```
Cache "playwright: ~/.cache/ms-playwright": Downloaded 265.9 MiB in 8 seconds
Cache "pnpm: ~/.local/share/pnpm/store":    Not found
```

같은 러너, 같은 스텝, 같은 캐시 기능인데 **한쪽은 되고 한쪽은 안 된다.** 이것으로 "CI 캐시 기능이 이상하다" "러너 환경 문제다" 축이 한 번에 지워지고 **경로 하나**만 남는다.

설치 로그의 `reused` 도 직접적인 신호다.

```
Progress: resolved 1114, reused 0, downloaded 842, added 266
```

캐시가 살아 있으면 `reused` 가 전체 수에 가깝게 나온다. **0 이면 스토어를 못 찾은 것이다.**

## 고치는 법 — 위치를 알아내지 말고 고정한다

처음엔 "폴백 위치를 알아내서 캐시 정의를 거기로 바꾸자"고 생각했는데, 이건 약하다.

- 폴백 위치는 **이미지·러너에 따라 달라질 수 있다**. glibc 이미지와 musl 이미지가 섞여 있으면 더 그렇다
- 한 번 맞춰 박아도 **이미지가 바뀌면 조용히 다시 빈 캐시**가 된다. 그리고 그때도 실패가 아니라 느려짐이라 신호가 없다

그래서 위치를 **명시**하는 편이 낫다. 워크스페이스 안쪽으로 주면 `node_modules` 와 같은 파일시스템인 게 보장된다.

```
pnpm install --frozen-lockfile --store-dir "$CLONE_DIR/.pnpm-store"
```
```yaml
caches:
  pnpm: .pnpm-store      # 같은 경로를 가리키게
```

**`.npmrc` 에 넣지 말 것.** 로컬에도 적용돼 개발자 머신의 스토어가 레포 안으로 들어온다. 로컬은 프로젝트 간 공유 스토어가 맞는 동작이다 — CI 스크립트에서만 주는 게 맞다.

그리고 **설치 스텝이 여럿이면 전부 붙여야 한다.** 하나만 고치면 캐시 정의는 한 벌인데 스텝마다 다른 경로를 쓰는 상태가 된다.

## 부수 효과 — 스토어가 레포 안으로 들어온다

폴백이든 `--store-dir` 이든, 스토어가 **체크아웃 디렉터리 안**에 생긴다. 그 트리를 훑는 도구가 전부 그걸 본다.

실제로 포맷터를 레포 전역에 처음 걸었을 때 **경고 1,185건·에러 8건이 전부 이 스토어**였다. 스토어 안의 `.d.ts` 를 JS 로 파싱하려다 난 SyntaxError 까지 포함해서. 로컬에는 그 디렉터리가 없어서 통과하고 **CI 에서만 터졌다.**

포맷터·린터는 대개 `.gitignore` 를 읽지 않고 자기 ignore 파일을 따로 본다. 그러니 세 곳을 같이 맞춰 두는 게 안전하다.

```
.gitignore         .pnpm-store/
.prettierignore    .pnpm-store
caches             .pnpm-store
```

## 검증

캐시는 **두 번 돌려야** 확인된다. 첫 런은 채우고 두 번째 런이 쓴다.

- 1회차: `Not found` → `Uploading`
- 2회차: `Downloaded` → 설치 로그에 `reused <전체 수>`

클론 디렉터리 안쪽을 캐시로 잡는 게 처음이라면 **복원 순서**도 한 번 확인해 두면 좋다. 로그에서 clone 이 캐시 복원보다 먼저면 문제없다 — clone 이 만든 트리 위에 캐시가 얹힌다.

## 한 줄

> 설정한 경로에 안 쌓이는 캐시는 **에러를 내지 않는다.** 느려질 뿐이라, 다른 이유로 로그를 열어 보기 전까지 아무도 모른다.
