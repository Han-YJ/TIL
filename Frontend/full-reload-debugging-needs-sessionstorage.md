# 전체 리로드를 거치는 버그는 console.log로 계측할 수 없다

간헐 버그를 잡으려고 `console.log`를 깔았는데 **아무것도 안 찍히는** 경우가 있다. 로그가 안 나가는 게 아니라, 그 사이 페이지가 통째로 리로드돼 콘솔과 메모리가 함께 비워진 것이다.

## 왜 문제가 되나

원인 자체가 리로드를 유발하는 종류면 계측이 매번 증발한다.

- 라우터가 이전 상태로 되돌아가며 문서를 다시 그리는 경우
- 세션 만료로 인증 경로로 튕기는 경우
- 개발 서버의 HMR이 풀 리로드로 떨어지는 경우

`window.__log = []` 같은 전역 배열도 같은 이유로 소용없다. 리로드 시점에 그 실행 컨텍스트가 사라진다.

브라우저 콘솔의 "Preserve log"를 켜면 로그 줄은 살지만, 로그를 **찍기 전에** 리로드가 나면 애초에 남을 게 없다. 그리고 재현이 간헐적이면 개발자 도구를 열어 둔 채 기다리기도 어렵다.

## 대응

`sessionStorage`에 적재한다. 같은 탭에서 리로드를 건너 살아남고, 탭을 닫으면 알아서 사라져 뒷정리도 필요 없다.

```js
const push = (label, data) => {
  const log = JSON.parse(sessionStorage.getItem('probe') ?? '[]');
  log.push({ t: Date.now(), label, ...data });
  sessionStorage.setItem('probe', JSON.stringify(log));
};
```

재현된 뒤 콘솔에서 꺼낸다.

```js
copy(sessionStorage.getItem('probe'));
```

- 절대 시각(`Date.now()`)을 함께 넣는다 — 리로드 전후 이벤트의 선후가 이것으로만 갈린다
- 용량 상한(탭당 수 MB)이 있으니 긴 문자열은 잘라서 넣는다
- `localStorage`는 탭·세션을 넘어 남아 이전 재현의 로그와 섞인다

## 한 걸음 더

로그가 "언제" 찍혔는지가 아니라 "무엇이 먼저였는지"가 필요하면, 계측 지점마다 단조 증가 시퀀스 번호를 같이 넣는다. 같은 밀리초에 여러 이벤트가 몰리면 타임스탬프만으로는 순서가 안 갈린다.
