# Playwright getByRole의 name은 부분일치다

버튼 하나를 찾는 단언이 갑자기 strict mode 위반으로 깨졌다.

```
Error: strict mode violation: getByRole('button', { name: '업로드' }) resolved to 2 elements
```

화면에 "업로드" 버튼은 분명 하나뿐이었다. 범인은 그 옆의 파일명 영역이었다 — 파일 미첨부일 때 **"로고 파일을 업로드해 주세요."** 라는 placeholder를 그리는데, 이 영역도 클릭하면 파일 선택기가 열리는 `<button>`이었다. 접근 이름에 "업로드"가 들어 있으니 같이 잡힌 것이다.

## 왜 걸리나

`getByRole(role, { name })`의 `name`은 **기본이 부분일치(substring)** 이고 대소문자·공백도 정규화해서 비교한다. 완전일치라고 착각하기 쉬운 지점이다.

```
접근 이름: "로고 파일을 업로드해 주세요."
쿼리:      { name: '업로드' }        → 매치됨
```

짧은 라벨일수록 위험하다. "추가", "삭제", "저장" 같은 두 글자 라벨은 주변 안내 문구·placeholder·툴팁에 그대로 들어 있는 경우가 흔하다.

## 대응

```ts
page.getByRole('button', { name: '업로드', exact: true })
```

`exact: true`를 주면 완전일치가 되고, 이때는 대소문자와 공백도 그대로 비교한다.

## 어느 쪽을 기본으로 둘까

기본값이 부분일치인 건 이유가 있다. 접근 이름은 아이콘·뱃지·시각 숨김 텍스트가 붙어 실제 값이 예상보다 길어지는 일이 잦아서, 완전일치를 기본으로 두면 오히려 안 잡히는 경우가 많아진다.

그래서 이렇게 나눠 쓰는 편이 편했다.

- **긴 고유 문구**(제목, 안내문) → 기본 부분일치. 접근 이름에 뭐가 더 붙어도 견딘다
- **짧은 공용 라벨**(추가·삭제·저장·업로드) → `exact: true`. 주변 문구에 섞여 들어갈 확률이 높다

덧붙여, strict mode 위반은 **테스트가 깨졌다는 신호이자 화면 구조를 알려주는 신호**이기도 하다. 위 경우도 에러 덕분에 "파일명 영역이 사실은 버튼이었다"는 걸 알게 됐다. 셀렉터를 좁히기 전에 잡힌 요소가 몇 개이고 각각 뭔지 먼저 확인해 보는 게 낫다.

```ts
console.log(await page.getByRole('button', { name: '업로드' }).allInnerTexts());
```
