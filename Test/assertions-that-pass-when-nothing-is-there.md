# 아무것도 없어도 통과하는 단언 — 초록을 근거로 삼기 전에

테스트가 초록인데 아무것도 지키고 있지 않은 경우가 있다. 단언의 종류에 따라 **실패할 수 없는** 것들이 있어서다.

## 존재 단언과 부재 단언은 대칭이 아니다

```js
// 존재 단언 — 셀렉터가 틀리면 못 찾아서 빨개진다
expect(screen.getByRole('button', { name: '저장' })).toBeVisible();

// 부재 단언 — 셀렉터가 틀려도 0건이라 초록이다
expect(screen.queryAllByRole('button')).toHaveLength(0);
```

존재 단언은 셀렉터에 오타가 나면 요소를 못 찾아 즉시 실패한다. **오타가 곧 신호**다.

부재 단언은 다르다. "없어야 한다"를 검사하는데, 셀렉터가 잘못돼서 못 찾은 것과 정말로 없는 것이 **같은 결과**를 낸다. 스코프를 잘못 잡아도, role 이름을 틀려도, 컴포넌트가 아예 렌더되지 않아도 전부 0건이고 전부 초록이다.

같은 함정에 걸리는 유형이 몇 가지 더 있다.

| 유형 | 예 | 왜 헛도나 |
|---|---|---|
| 부재 | `toHaveCount(0)` · `not.toBeInTheDocument()` | 못 찾은 것과 없는 것이 같은 결과 |
| 권한 게이팅 | "뷰어에게는 편집 버튼이 안 보인다" | 세션이 안 붙어 화면 자체가 안 떠도 통과 |
| 계약 | "뒤로 가면 이전 대상으로 돌아간다" | 애초에 이동이 없었어도 통과 |
| 상태 전파 | "자식이 부모에 보고한다" | 자식이 렌더되지 않았어도 통과 |

뒤의 둘이 특히 위험하다. 화면이 그럴듯하게 나와서 **사람 눈으로 봐도 통과로 보인다.**

## 확인법 — 조건을 뒤집어 빨간 것을 본 적이 있는가

방법은 단순하다. **그 단언이 실패해야 마땅한 상황을 만들어 실제로 실패하는지 본다.** 빨간 걸 한 번도 못 봤으면 그 초록은 아무 근거가 없다.

뒤집는 축은 단언의 종류마다 다르다.

- 권한 게이팅 → 역할을 뷰어에서 편집자로 바꾼다
- 부재 → **같은 셀렉터를 그 요소가 실제로 있는 화면에 걸어 본다**
- 계약("이전 대상으로") → 이동 경로를 하나 줄여 본다
- 상태 전파 → 자식의 보고를 끊어 본다

부재 단언에서 세 번째 방식이 특히 잘 듣는다. 예를 들어 "이 화면에는 정렬 컨트롤이 0개"를 단언했다면, 같은 셀렉터를 정렬이 있는 다른 화면에 걸어 본다.

```js
// 임시 — 반드시 실패해야 정상이다
test('MUST FAIL: 정렬이 있는 화면에서도 0건이면 셀렉터가 헛돈다', async ({ page }) => {
  await page.goto('/somewhere-with-sortable-headers');
  await expect(page.locator('thead button')).toHaveCount(0);
});
```

빨개지면 셀렉터가 실제로 버튼을 찾는다는 뜻이고, 원래 화면의 "0건"이 비로소 의미를 갖는다. 확인이 끝나면 이 임시 테스트는 지운다.

실제로 돌려보면 숫자가 나온다 — 한쪽에서 8건, 다른 쪽에서 1건이 잡히는 식이다. 그 숫자가 근거다.

## 논증으로 대체하지 않는다

여기서 흔히 하는 타협이 있다. "같은 파일의 다른 단언이 이 스코프가 실재함을 이미 증명하니까 괜찮다" 같은 논증이다.

그럴듯하지만 **덮는 범위가 다르다.** 스코프가 실재한다는 것과, 그 셀렉터가 찾으려는 요소를 실제로 찾을 수 있다는 것은 다른 명제다. 스코프는 멀쩡한데 role 이름이 틀렸으면 여전히 0건이고 여전히 초록이다.

빨간 걸 보는 데 드는 비용은 임시 테스트 하나에 몇 초다. 논증은 그보다 싸지 않다.

## 확인이 불가능한 단언은 그렇다고 적는다

가끔 뒤집을 수 없는 것도 있다. 실패 상태를 만들 방법이 없는 경우다 — 서버가 항상 성공을 주도록 되어 있다든가, 데이터가 고정이라 다른 분기에 도달할 수 없다든가.

그럴 땐 통과했다는 사실을 근거로 세지 않고 **"확인 불가"로 남긴다.** 커버리지 문서에 초록으로 적어두면 나중에 "그건 테스트가 검증했다"는 사실 진술로 전파되고, 그게 아무 근거가 없다는 것은 아무도 모른다.

## 정리

- 존재 단언은 틀리면 빨개진다. 부재·게이팅·계약·상태 전파 단언은 **틀려도 초록일 수 있다**
- 그런 단언은 조건을 뒤집어 **빨간 것을 한 번 본 뒤에야** 근거가 된다
- 뒤집을 수 없으면 초록으로 세지 말고 확인 불가로 적는다
